═══════════════════════════════════════════════════════════════
  ERROR DESCRIPTION
═══════════════════════════════════════════════════════════════

Error Message:
  h11._util.LocalProtocolError: Can't send data when our state is ERROR

Error Type:
  HTTP Protocol Error (h11 library)

Root Cause:
  The server tried to send a response after the HTTP connection was 
  already in an ERROR state. This happens when:
  
  1. An exception occurs during response streaming
  2. The client disconnects before response is fully sent
  3. A timeout occurs during a long-running operation
  4. Multiple responses are attempted for the same request
  5. ExceptionGroup errors from anyio TaskGroup are not handled

═══════════════════════════════════════════════════════════════
  WHY IT HAPPENED
═══════════════════════════════════════════════════════════════

1. EXCEPTIONGROUP NOT HANDLED
   - Python 3.11+ and anyio use ExceptionGroup for task errors
   - Your error handler didn't catch ExceptionGroup
   - When a task failed, it created an ExceptionGroup
   - The error handler tried to send a response
   - But the connection was already in ERROR state

2. MISSING CONNECTION HANDLER
   - main.py imported ConnectionHandlerMiddleware
   - But the middleware class didn't exist!
   - This caused import errors and missing error handling

3. H11 PROTOCOL ERRORS NOT PROPERLY HANDLED
   - When h11 errors occurred, the handler tried to send JSONResponse
   - But the connection was already closed
   - This caused cascading errors

═══════════════════════════════════════════════════════════════
  WHAT THE ERRORS MEAN
═══════════════════════════════════════════════════════════════

ExceptionGroup:
  - Container for multiple exceptions from async tasks
  - Used by anyio's TaskGroup
  - Occurs when parallel tasks fail
  - Example: Multiple API calls failing simultaneously

LocalProtocolError:
  - HTTP protocol state machine error
  - Connection is in wrong state for operation
  - Usually means connection is closed/broken
  - Cannot send data when state is ERROR

TaskGroup Errors:
  - Async task group had unhandled exceptions
  - Multiple tasks can fail independently
  - All failures collected into ExceptionGroup
  - Need special handling to extract sub-exceptions

═══════════════════════════════════════════════════════════════
  PREVENTION TIPS
═══════════════════════════════════════════════════════════════

1. Always handle ExceptionGroup in Python 3.11+
2. Never try to send response after connection error
3. Check client connection before long operations
4. Use proper async exception handling
5. Log all sub-exceptions in ExceptionGroup
6. Return None for h11 errors (don't send response)
7. Add connection state checks in middleware
