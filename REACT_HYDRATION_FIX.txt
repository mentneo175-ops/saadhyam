═══════════════════════════════════════════════════════════════
  WHAT ARE HYDRATION ERRORS?
═══════════════════════════════════════════════════════════════

Hydration = React attaching to server-rendered HTML

When server HTML doesn't match client React:
❌ React shows hydration mismatch warnings
❌ Console gets flooded with errors
❌ Users see warnings in browser console
✅ App still works, but looks unprofessional

═══════════════════════════════════════════════════════════════
  WHY THESE ERRORS HAPPEN
═══════════════════════════════════════════════════════════════

1. INVALID HTML NESTING
   - HTML has strict nesting rules
   - <p> can only contain inline elements
   - <div> is a block element
   - React enforces these rules

2. BROWSER EXTENSIONS
   - Grammarly, LastPass, etc. modify HTML
   - They add attributes before React hydrates
   - Server HTML doesn't have these attributes
   - React sees a mismatch

3. DYNAMIC CONTENT
   - Date.now() or Math.random()
   - Different values on server vs client
   - Causes hydration mismatch

═══════════════════════════════════════════════════════════════
  PREVENTING FUTURE HYDRATION ERRORS
═══════════════════════════════════════════════════════════════

✅ DO:
1. Use <div> for containers with nested elements
2. Use <span> for inline text
3. Add suppressHydrationWarning for extension-prone elements
4. Use useEffect for client-only code
5. Keep server and client rendering identical

❌ DON'T:
1. Put <div> inside <p>
2. Use Date.now() or Math.random() in render
3. Use typeof window checks in render
4. Modify HTML with browser extensions during dev
5. Use different data on server vs client

═══════════════════════════════════════════════════════════════
  COMMON INVALID HTML NESTING
═══════════════════════════════════════════════════════════════

❌ INVALID:
<p><div>...</div></p>          → div in p
<p><h1>...</h1></p>            → heading in p
<button><button>...</button>   → button in button
<a><a>...</a></a>              → link in link
<table><div>...</div></table>  → div in table

✅ VALID:
<div><div>...</div></div>      → div in div
<p><span>...</span></p>        → span in p
<div><button>...</button></div> → button in div
<div><a>...</a></div>          → link in div
<table><tr><td>...</td></tr>   → proper table structure
